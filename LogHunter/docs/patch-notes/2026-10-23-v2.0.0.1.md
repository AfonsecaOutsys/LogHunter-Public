# LogHunter v2.0.0.1

Date: 2026-10-23

Hotfix on top of `v2.0.0`. Contains only the ALB region detection fix below.

## Included in this release

- Fixed ALB region detection from the S3 bucket name.

## ALB region detection fix

New ALB configurations derive the AWS region from the bucket name (`<guid>-<region>-alblogs`). The previous pattern let the match start at any `af-` or `ca-` inside the bucket GUID, so a bucket such as:

`aa56559e-af22-443b-a105-7d34b77b4faf-us-east-1-alblogs`

resolved to `af-us-east-1` instead of `us-east-1`. The S3 prefix then pointed at a non-existent path, `aws s3 ls` returned an empty listing with a non-zero exit code, and planning failed with `aws s3 ls failed for s3://...`.

- the region must now start at a word boundary and have the shape `<prefix>-[gov-]<name>-<digit>`
- applied to both the web shell planner (`AlbDownloadPlanner`) and the console flow (`AlbDownload`)
- roughly 1 in 25 GUID-named buckets were affected

Saved configurations created with an older build keep the region they were saved with. If a saved config shows an invalid region (for example `af-us-east-1`), recreate it or edit `Region` in `ALB/configs/<name>.json`.
