# LogHunter v2.0.0.5

Date: 2026-11-26

Patch on top of `v2.0.0.4`. Merges `feature/usage-tracking`.

## Included in this release

- Anonymous usage counts for app starts and workflow runs.

## Usage counts

Goal: know how often LogHunter is started and which workflows are used, with no personal data.

- **Server:** OutSystems service module `LogHunterUsage_IS` (personal environment), endpoints `POST /rest/Usage/AppStart` and `/FeatureUse`. Contract and decisions: `LogHunter/docs/handoff-usage-api.md`, design: `LogHunter/docs/usage-tracking-plan.md`.
- **Payload:** install id (random GUID kept in `config\install-id`), session id (new per launch), version, mode (`web` / `console`), and for FeatureUse the workflow key. The server sets the timestamp.
- **Coverage:** all 23 workflow keys (`UsageFeature`), in web mode (API handler after a successful start) and console mode (start of the scan). IP sweep sends a `section` field so ALB and IIS sweeps are counted separately. The startup IP-range refresh, the ALB download child process and the SQLite viewer child process are never counted.
- **Behaviour:** background send, 3 s timeout, every failure swallowed; one local trace event per call (`usage` / `sent` or `failed`), never with the key.
- **Configuration:** endpoint and key come from `certs\usage.props` (gitignored), embedded only in Release builds. Debug builds and builds without the file send nothing.
- **Opt-out:** `LOGHUNTER_NO_USAGE=1`. A console notice at start; README section "Usage counts".
- **Verified:** live end to end (AppStart in web and console mode, FeatureUse for sweep and IP-range actions, all HTTP 200), and opt-out sends nothing. 133 unit tests, none of them against the live endpoint.

## Operator notes

- The current key is a test key. To rotate it, update `certs\usage.props` and publish again. No code change is needed.
- Every Release build reports usage, including a future public build, as agreed in the handoff.
