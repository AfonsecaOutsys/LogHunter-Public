# LogHunter v2.0.0.3

Date: 2026-11-23

Patch on top of `v2.0.0.2`. Merges `feature/iis-burst-scoring`.

## Included in this release

- IIS Burst Patterns: one shared scoring engine for console and web shell.
- Fewer false burst candidates on busy legitimate traffic.
- Web shell Scan campaigns panel for rotating-IP scans.
- Burst table column tooltips and highlighted 4xx%.

## Shared burst scoring

Threshold, scoring, flag and severity logic moved out of the console option and the web job into `LogHunter/Services/IisBurstScoring.cs`. Before this, `IisOption_FindBurstPatterns` and `IisBurstPatternsJobManager` each carried their own copy and could give different verdicts for the same logs.

## Threat-signal gate

A burst is flagged only when it shows real threat signals:

- strong path enumeration, or
- errors (4xx/5xx) together with volume, enumeration or a narrow endpoint focus.

High-rate, POST-heavy, or single-endpoint traffic answered with `200` responses (busy legitimate apps, health checks, integrations) is no longer reported as a candidate.

## Scan campaigns (web shell)

A new panel groups bursts that share the same user-agent and the same set of distinct paths into one campaign. A scan that rotates source IPs shows up as one campaign with many IPs, instead of many unrelated low-severity bursts.

Limitation: a flood where each IP sends only a few requests never forms per-IP bursts, so it does not appear as a campaign. That case is tracked in `docs/ticket-gap-plan.md` (G9).
