# LogHunter v2.1 Backnote

Date: 2026-10-23 (updated 2026-11-26)

Folded into the v2.1 release notes on 2026-11-26 (`2026-11-26-v2.1.md`). Kept for history.

## Carry forward from v2.0.0.1

- ALB region detection from the S3 bucket name no longer picks up `af-` / `ca-` fragments inside the bucket GUID (for example `af-us-east-1` instead of `us-east-1`), which made ALB listing and download fail for affected buckets. Fixed in both web shell and console flows.

## Carry forward from v2.0.0.2

- ALB download page no longer sticks on a previous job's status when a second download is started right after the first; a second Start while one is running switches the page to the running job.
- Start download returns immediately; the AWS CLI checks run in the background job.
- Always-on diagnosis trace: a JSON-lines trace of every web request, browser action, ALB job step, AWS CLI call and console menu choice in `logs\trace-<timestamp>.jsonl`, credentials masked, files older than 10 days removed at startup, with a console notice on where to send it for bug reports.
- IIS Burst Patterns severity colors follow the severity score (CRIT and MED rows colored again).
- ALB download empty-listing error suggests checking the Sentry toggle.

## Carry forward from v2.0.0.3

- IIS Burst Patterns: console and web share one scoring engine (`IisBurstScoring`), so the two surfaces cannot drift apart.
- Bursts are flagged only with real threat signals (strong enumeration, or errors alongside volume, enumeration or focus). Busy legitimate apps no longer surface as candidates.
- Web shell **Scan campaigns** panel groups bursts by user-agent + URL set to expose rotating-IP scans; burst table columns have tooltips and a highlighted 4xx% column.

## Carry forward from v2.0.0.4

- IP sweep (ALB and IIS): unlimited IPs, CIDR blocks and ranges across several log folders in one run; hit/no-hit per target with scope, customer-safe HTML report and Excel; hand-offs to IP Summary and AbuseIPDB.
- CDN and proxy range intelligence refreshed in the app (Cloudflare, CloudFront, Akamai, Imperva, Fastly, F5 XC, Azure Front Door, Zscaler, and others), IP ranges pill and page, customer-pasted ranges.
- CDN / proxy badges and "Fronted by" banner in ALB and IIS results.
- IIS client IP read right to left through X-Forwarded-For, skipping CDN edges; 0.0.0.0, CGNAT and private IPv6 never reported as the client. ClaimedClient and X-Forwarded-For columns in IIS IP summary exports.
- ALB Start download locked while a job runs.

## Carry forward from v2.0.0.5

- Anonymous usage counts: one event per launch and per workflow run (install id, launch id, version, mode, workflow name only), background and silent on failure, `LOGHUNTER_NO_USAGE=1` to turn off, console notice and README section.

## Suggested short release-note wording

- Fixed ALB region detection for S3 buckets whose GUID produced an invalid region, which caused `aws s3 ls failed` during ALB downloads.
- Fixed the ALB download page showing a previous job's status after starting a new download.
- Added an always-on diagnosis trace (kept 10 days) for bug reports.
- Fixed IIS Burst Patterns severity colors.
- IIS Burst Patterns now flags only bursts with real threat signals and groups rotating-IP scans into scan campaigns.
- Added IP sweep for any number of IPs, CIDR blocks and ranges across ALB and IIS logs.
- Added CDN and proxy labels so CDN edges are no longer mistaken for attackers.
- Fixed IIS client-IP resolution for forged and CDN X-Forwarded-For chains.
- Added anonymous usage counts (opt out with `LOGHUNTER_NO_USAGE=1`).
